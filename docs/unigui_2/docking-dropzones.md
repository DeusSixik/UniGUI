# Docking drop-зоны: крест + live tear-off (unigui_2, шаг 3)

Во время драга виден крест зон над целевым листом, превью живое.
Триггеры срабатывают по наведению мыши — и только они. Краевых полос нет.

## Триггерная модель (единственная точка истины)

Оффер существует ровно там, где нарисован триггер. Квадрантной
fallback-геометрии нет: между триггерами — мимо зон (окно остаётся плавать),
а не «ближайшая сторона».

Приоритет: таб-стрип → ячейка креста листа:
- Таб-стрип: любой стрип (`tabStripAt`) — таб в лист стрипа.
- Ячейка креста: `crossCellRect` (публичная, shared с рендером).
- Общий резолвер `triggerAt` используют intent, merge и redock — один код.

## Live tear-off: выход из таб-зоны

Таб отрывается в окно сразу при выходе мыши из коллизии таб-зоны
(не на release): панель извлекается, окно создаётся под курсором хедером
под указатель, capture и drag-состояние передаются окну (`takeoverDrag`),
дальше жест идёт штатным window-путём (триггеры, превью, дроп).

- `DockDragController.handoff` завершает таб-фазу (`drag-ended(dropped=true)`,
  preview гаснет), ничего не дропает повторно.
- Уважается `tearOffOnDragOut`; единственная панель заживо не вырывается
  (пустой root никому не нужен, release-путь вернёт её snap-back'ом).
- Окно сразу показывает превью под точкой handoff, крест догоняет
  со следующего движения мыши.

## Reorder табов внутри таб-зоны

Пока мышь двигается внутри стрипа домашнего листа, наведение на соседний
таб ставит тащимую панель на его место (`reorderPane`/`movePaneBefore`,
остальные сдвигаются, тащимая остаётся выделенной). Повторы — no-op.
Кросс-листовые перемещения идут окном через зону (см. выше).

## Релиз мимо триггеров — остаётся плавать

Релиз плавающего окна над root, но мимо креста/стрипа, НЕ прибивает панель
табом в чужой лист: окно остаётся плавающим, превью гаснет. Раньше такое
прилипание было багом («отпустил инспектор — он прикрепился к Scene»).
Докирование происходит только по триггеру; пустой root принимает дроп
anywhere (целиться там не во что).

## Память размера окна

Tear-off возвращает окну прошлый размер, а не размер листа: при доке размер
окна запоминается за id панели (`floatingWindowSizes`), при отрыве
восстанавливается. Первый отрыв (панель ещё не плавала) — размер исходного
листа, кламп `[180..640]×[112..480]`.

## Мышь, а не окно

Превью шло по мыши, а дроп плавающего окна — по прямоугольнику окна
(`floatingWindowDropX/Y` от позиции окна + половина ширины): оффер и результат
расходились на offset захвата. Теперь всё по мыши:
- `WindowWidget.lastDragRootX/Y` — трекинг указателя в драге (публичный API).
- Redock-listener превью и дропа идёт по нему; хелперы точки-от-окна удалены.
- Preview == drop всегда: один резолвер, одни координаты.

## Контракт поведения

- **Крест над листом**: 5 ячеек (верх/лево/центр-таб/право/низ) по центру
  листа под курсором. Ячейка = `clamp(min(w,h)*25%, 40, 64)px`, зазор 6px.
  Верхняя ячейка с плашкой (метафора таба), центр с глифом слоёв,
  боковые — со стрелками к краям сплита.
- **Геометрия честная**: хит-тест повторяет нарисованное 1-в-1 —
  ячейки `crossCellRect` не пересекаются. Что подсвечено, туда и примит.
- **Якорь креста**: целевой лист intent'а; если intent пуст (таб-драг) —
  лист под курсором; если нависло floating-окно мимо триггеров — лист под
  указателем по координатам intent. Крест следует за курсором (инвалидация
  на каждый move драга).
- **Приоритеты**: таб-стрип > зоны листа > float. Дроп на табы всегда таб.
- **Превью**: полупрозрачная акцентная заливка + рамка по bounds intent'а.
- Активная зона подсвечена акцентом, остальные тусклые.

## Совместимость

- `DockDropIntent` не менялся (record цел). `tabbed()`/`split()` работают
  как раньше.
- `DockingManager.splitRoot/splitRootPane` удалены вместе с краевыми зонами;
  снапшоты сериализуют дерево как раньше (дерево-based, без изменений кодека).
- `DockingManager.reorderPane` + `DockNode.movePaneBefore` — новые методы
  для live reorder.
- `WindowWidget.takeoverDrag` — новый публичный API приёма жеста.
- `DockDragController.handoff` — завершение таб-фазы при live tear-off.
- Foreign-окна: дроп идёт через тот же `insertMergedPane` (теперь возвращает,
  вставил ли; `false` = мимо триггеров = окно остаётся плавать).

## Tear-off: вынос мимо зон (release-путь)

Вытянул таб/панель и отпустил мимо всех зон — панель становится плавающим
окном, а не возвращается назад (`DockingRoot.tearOffOnDragOut`, default true;
откат — `tearOffOnDragOut(false)`).

- Срабатывает только после реального драга (порог пройден) и только вне
  исходного листа: дроп единственной панели над собой — snap-back, клик без
  движения — ничего. Кликовая семантика не меняется.
- Окно при создании клампится в хост штатным путём
  (`createFloatingPaneWindow`), поэтому `allowFloatingOutsideHost` продолжает
  управлять только свободным движением, но не самим отрывом.
- Старый контракт «за хостом без флага — панель остаётся» заменён:
  соответствующий тест обновлён на tear-off.
