# Перепроектирование Style + Theme

Цель: темы, максимально удобные для пользователей API. Текущая архитектура
ужасна и архитектурно, и идейно — переписываем обе части. Связано с
`html-reference.md` (токены фиксируются там первыми) и `widget-audit.md`
(уход `themeEnabled(false)`-костылей).

## Диагноз текущей системы (факты из кода)

1. **Тема затирает значения пользователя.** Паттерн повсюду:
   `trackColor.set(styleValue(TRACK_COLOR, trackColor))`
   (`Slider:211`, `ScrollBar:242`, `TextInput:290`...). Fallback — живое поле
   виджета, `applyTheme()` пишет в него каждый рендер. Свой цвет живёт до
   первого обновления версии стиля. Чьё значение выживет — решает порядок
   вызовов. Поэтому код усыпан `themeEnabled(false)` (внутренности `TreeView`,
   `ColorPicker`, демо, тултипы) — тему отключают целиком, лишь бы не драться.
2. **Рендер мутирует состояние.** `applyTheme()` дёргается из `renderContent`.
   Рендер обязан быть чистой функцией от состояния, иначе нет ни кэширования,
   ни детерминизма, ни отладки.
3. **Три системы вместо одной.** `Theme` (тип→стиль) + `localStyles`-мапа на
   каждом виджете + `StylePack` (селекторы/классы/XML/анимации) + `StylePackXml`
   + `MutableStyle`/`ResolvedStyle` — ~20 файлов API на задачу «задать цвета».
4. **Нет слоя токенов.** `DefaultTheme` — простыня `put()` на тип × состояние
   (`BG_1`, `BG_2_HOVER`, `ACCENT`...). «Акцент синим везде» = десятки
   переопределений. Освежить весь UI одним движением невозможно физически.
   Цвета при этом дублируются хардкодом по конструкторам
   (`background().set(0.025, 0.030, 0.040, ...)` в `DropDownBox`, `ComboBox`...).
5. **Версионирование гуляет по родителям каждый кадр.** `renderCached` считает
   `version * 31 + localStyle(type).version()` вверх по дереву
   (`WidgetBase:1713`) — O(глубина) lookup'ов на виджет на кадр за то, что
   плоская тема вообще не должна стоить.

## Новая система: идея

Тема = плоские токены + вычисляемые дефолты виджетов из токенов. Явное значение
пользователя всегда побеждает и никогда не затирается. Резолв — один раз при
инвалидации, рендер только читает снапшот.

## Слои резолва (строгий приоритет)

1. Явно заданное на виджете (`background().set(...)` помечает поле
   dirty-user — тема его больше не трогает никогда).
2. Локальный override (`widget.themeOverride(...)` — точечно, без отключения
   всей темы; замена сегодняшних `themeEnabled(false)`).
3. Стиль типа из темы (`styleFor`, значения читаются из токенов).
4. Токены темы (`colors().accent()`, `shapes().radiusMd()`...).
5. Жёсткий дефолт виджета (сегодняшние константы, последний fallback).

## API для пользователя (скетч, не финальные имена)

```java
// Своя тема за 10 строк вместо простыни put'ов:
Theme editorDark = Theme.dark()
    .accent(0x4A9EFF)
    .surface(0x1E2126, 0x23262C)
    .radius(8.0f)
    .build();
ui.theme(editorDark); // всё приложение перекрасилось

// Точечно, не вырубая тему целиком:
myButton.themeOverride(o -> o.background(accent).radius(8));
myButton.background().set(...); // explicit — побеждает всё, переживает смену темы
```

## Ключевые решения

- **Токены** — один иммутабельный `ThemeTokens`
  (colors / shapes / typography / spacing). Смена темы = один `version++`
  в корне + один проход инвалидации. Никаких гуляний по родителям в рендере:
  версия хранится плоско, виджет подписывается один раз.
- **Смерть `applyTheme()` в рендере.** Вместо него `resolveTheme()` по
  инвалидации (смена темы/состояния/override), результат — снапшот.
- **Состояния формулой, не сотней `put`ов.** Hover/pressed/disabled
  вычисляются от токенов (`accent.hover = accent.lighten(8%)`). Это же
  централизованно чинит «пилюли vs full-bleed».
- **`StylePack`/селекторы/XML не удаляем** — сажаем сверху опциональным слоем
  «продвинутый режим», базовый путь — токены. Старые `put()`-темы работают
  через адаптер `LegacyThemeAdapter` (обратная совместимость, затем депрекейт).
- **Переименования** — только по правилам из `widget-audit.md`
  (новое имя + `@Deprecated`-мост, XML-имена не трогать без мигратора).

## Миграция

1. Токены + резолвер (ядро, без виджетов).
2. `SurfaceWidget` / `Button` / `TextInput` — покрывают ~80% картинки.
3. DropDown/Popup хром (пилюли, зазоры, шеврон слотом).
4. Остальное по матрице аудита; старый API — депрекейт, не слом.

## Починено: customTextColor poisoning (тёмный текст после нажатия)

Симптом: после нажатия текст кнопки оставался тёмным (`TEXT_ON_ACCENT`
pressed-цвета) навсегда — на вернувшемся тёмном фоне читался как чёрный.

Цепочка: `Button.applyTheme` анимирует `textColor` к pressed-значению
(transition 0.12s из темы); тики анимации пишут в `textColor` напрямую,
а `onChanged`-слушатель помечал ЛЮБУЮ запись как `customTextColor`
(`updatingTheme` покрывал только синхронный вызов, не тики) → флаг
`customTextColor` взводился навсегда → `applyTheme` early-return →
текст заморожен, фон продолжает темиться. Тот же яд действовал бы на
checked-текст тоглов (`TEXT_ON_ACCENT`).

Фикс: пометка custom — только в явных сеттерах
`textColor(ColorView)`/`textColor(float...)`; тики theme-анимаций флаг
не трогают (слушатель оставил только инвалидацию). Прямая мутация через
`textColor()`-хэндл больше не защищает от темы — задокументированный
трейд-офф (бой с темой за один цвет и раньше был сломан).
Тест: `testPressedButtonTextColorRestoresAfterRelease`.
