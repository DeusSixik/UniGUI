# MainTODO — стили и темы

Решения по перепроектированию Style/Theme. Формат не меняется:
остаётся XML `StylePack`, CSS-текст не заводится.

## Решения

1. Формат один — XML `StylePack`. Селекторы, классы и состояния остаются
   его. Новый текстовый синтаксис не вводится.
2. На виджете строка стиля разрешена везде. Лямбда `style(s -> ...)` —
   рядом, как вариант с проверкой компилятором. Готовый стиль пишется
   заранее и применяется по классу.
3. Токенов в первой версии нет. Резолв проектируется так, чтобы слой
   токенов встал между правилом и дефолтом виджета без переписывания
   виджетов.
4. Конфликт свойств решает порядок: побеждает последнее добавленное
   правило. Нижнее перекрывает верхнее. Специфичность селектора не
   используется.
5. Состояния — только существующий `WidgetState`. Новых не заводим.
   При необходимости правится сам набор состояний.
6. Пакет и строка задают только визуал. Раскладка остаётся в `layout(...)`.
7. Разбор мягкий. Годные свойства применяются, битые копятся в диагностику
   и видны в редакторе. Пакет с опечаткой не роняет игру. Это уже умеет
   `StylePackXml.parseEditor`.
8. Стили не используют `widget.id()`. Точечный стиль — строковое поле
   `styleId` (одно). Переиспользуемый — список `styleClasses`, потому что
   на виджете их может быть несколько сразу (`primary danger`).

## Уже есть

- `StyleSelector` по типу, классу и `styleId`.
- `WidgetBase.styleId` и `styleClasses` со строковым вводом.
- `StylePackXml.parseEditor` с диагностикой без падения.
- `StylePack` применяется как `Theme`.
- `ThemeTokens` с группами цветов, форм, типографики и отступов подключены
  как fallback-слой в `MutableTheme` и `StylePack`.

## Дыры

- `applyTheme()` зовётся из рендера и затирает явные значения виджета.
  Отсюда `themeEnabled(false)` по всему коду.
- Базовые контролы ещё не переведены с повторяющихся hardcoded-значений на
  именованные токены.

## Порядок работ

1. Явное значение виджета побеждает тему и не затирается. Рендер больше
   не пишет в состояние.
2. Порядок правил вместо специфичности. Нижнее побеждает.
3. `widget.style(String)` и `widget.style(лямбда)` пишут в один набор
   явных свойств.
4. [x] Зафиксировать контракт слоя токенов в
   [`style-token-layer.md`](style-token-layer.md): группы, порядок резолва,
   версии и совместимость. На этом шаге без массовой миграции виджетов.
5. Перевести базовые виджеты на значения токенов и подключить локальные
   override без отключения всей темы.
6. Убрать `themeEnabled(false)` там, где он держался только из-за затирания.

## Обязательная демонстрация

Каждая добавленная фича должна иметь пользовательский пример использования. Для API это отдельная команда /unigui style (и последующие тематические команды), для XML/редактора — пример в документации или демо-экране. Фича не считается завершённой, пока пример не показывает рабочий сценарий.
