# ISF: архитектура независимых визуальных рецептов

## Главный принцип

ISF-рецепт является не игровым рецептом Minecraft, а независимым документом отображения.
Импорт из RecipeManager, тегов или loot table создаёт начальную копию ISF-документа. После
импорта изменение исходного рецепта не меняет ISF-документ, а изменение ISF-документа не
регистрирует и не модифицирует настоящий игровой рецепт.

## Слои

- `definition` хранит recipe type, recipe, параметры, визуальное дерево и выражения.
- `runtime` разрешает наследование и строит итоговый документ для отображения.
- `trigger` сопоставляет игровые или внешние события с рецептами и открывает их игроку.
- `persistence` хранит открытые рецепты и закладки в данных конкретного мира.
- `importer` создаёт независимые определения из Minecraft и других модов.
- `client` отображает браузер рецептов и в будущем размещает визуальное дерево через UniGUI.

## Наследование

Recipe type может наследовать другой recipe type. Recipe сначала наследует свой type, затем
опциональный родительский recipe и только после этого применяет собственные параметры и visual.
Циклы и отсутствующие родители являются ошибками загрузки, а не молча игнорируются.

## Параметры и будущий Node Editor

Recipe type объявляет типизированные параметры. Recipe задаёт их значения. Свойство визуального
узла хранит либо literal, либо expression. Expression использует именованные операции из реестра
функций и ссылки на параметры, поэтому будущий Node Editor сможет сериализовать граф в тот же
runtime-формат. Например, `percent(energy, maxEnergy)` можно передать в свойство `ProgressBar.value`.

Редактор не должен исполнять произвольный Java-код. Новые функции регистрируются модами через
публичный реестр и получают только типизированный evaluation context.

## Триггеры

Trigger идентифицируется `ResourceLocation`, а не enum. Встроенные id: `isf:craft`, `isf:use` и
`isf:station`. Другие моды могут зарегистрировать новый тип и вызвать его через API, не создавая
compile-time зависимость между ISF и вызывающим модом.

Recipe type сам по себе не отображается: открываемой сущностью является только recipe с хотя бы
одной trigger binding.

## Данные мира

Открытые рецепты и закладки хранятся в `SavedData` мира по UUID игрока. Клиент получает снимок
с сервера. Таким образом, одиночные миры и разные серверы не используют общий файл закладок.

## Генерация

`/isf generateRecipes [selectors]` создаёт независимый datapack мира `datapacks/isf_generated`.
JSON-рецепты находятся в `data/isf/isf/recipes/generated`. После генерации применяется обычный
`/reload`: это намеренная граница, чтобы запись файлов и замена рабочего registry оставались
раздельными транзакциями. Положительный селектор включает категорию, отрицательный (`-category`)
исключает её; несколько значений разделяются запятыми. Первая очередь: shaped, shapeless, furnace,
item tags, block/chest/entity loot.
